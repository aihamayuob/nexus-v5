## 2) الطريقة (INSPECT → MAP → DIAGNOSE)
**MAP (حقائق من قراءة الكود)**: `main.js` ينفّذ بالترتيب `applyTheme(); applyTranslations(); autoInitApp(); registerServiceWorker(); updateOnlineStatus();` — `autoInitApp()` **غير مُنتظَر**، وأول `await` فيه (`localStore.get('nexus_device_key')`) يعيد التحكم ⇒ `updateOnlineStatus()` يعمل متزامناً قبل الاستعادة. عند `navigator.onLine===false` تستدعي `logActivity('انقطع الاتصال', …)` الذي يُعيد ربط `activityLog` (`unshift` + `slice`) ويستدعي `renderActivityLog()`. لاحقاً `restorePersistableState(decrypted)` يُسند `activityLog = decrypted.activityLog` (أو `default()` = `[]` إن غاب المفتاح).
**DIAGNOSE**: الترتيب يجعل الفقد متوقَّعاً ⇒ اختبار runtime حقيقي بدل الاكتفاء بالاستنتاج.

**القياس**: `e2e/phase2-core-slice5-flows.mjs` — Chromium حقيقي، HTML + modules الحقيقية، `autoInitApp`/`persistState`/`localStore`/`encryptState` الحقيقية، بلا mocks. «offline» = `BrowserContext.setOffline(true)` (محاكاة شبكة Chromium نفسه)؛ الصفحة تُخدَّم عبر `context.route` من `https://nexus.test` (سياق آمن ⇒ `crypto.subtle` موجود) لأن المستند لا يمكن جلبه من خادم حقيقي والسياق offline. لكل إقلاع: سياق جديد (IndexedDB جديد)، بذر `activityLog` + علامة في `messages` عبر `persistState()` الحقيقي، ثم إعادة تحميل (online أو offline). متغيّران: **plain** (فقط قراءة `navigator.onLine` عند بداية المستند) و**traced** (hooks: `Array.prototype.unshift` لتوقيت كتابة المدخل، وغلاف على جسر `window.PersistableStateCore.restorePersistableState` لقراءة `activityLog` قبل/بعد) — للتفسير فقط، ويجب أن يوافق plain.
