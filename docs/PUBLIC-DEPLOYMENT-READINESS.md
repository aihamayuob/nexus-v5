# NEXUS — جاهزية النشر العام والتشغيل الحقيقي — 2026-11-21

**الخلاصة:** أُضيف **TLS داخلي اختياري** إلى الخلفية (VERIFIED محليًا). **لا يُدّعى أن النظام «جاهز للإنترنت»**: الحالة العامة **PARTIAL**. إنشاء حساب استضافة ومفاتيح مزودين **لا يمكنني تنفيذه** (يتطلب هوية صاحب الحساب وموافقة الفوترة وشروط الخدمة والمصادقة الثنائية) — الخطوات أدناه تأخذ دقائق منك، وبعدها أنفّذ الباقي.

## 1) ما نُفِّذ (كود + اختبار)
- `NEXUS_TLS_CERT_FILE` + `NEXUS_TLS_KEY_FILE` (ملفا PEM): كلاهما فارغ ⇒ HTTP كما كان (لا تغيير في أي تشغيل حالي)؛ كلاهما مضبوط ⇒ HTTPS (TLS ≥ 1.2) مباشرةً؛ واحد فقط أو ملف غير مقروء ⇒ **يُجهض الإقلاع** (لا رجوع صامت إلى النص الصريح؛ رسالة الخطأ تحمل رمز errno فقط).
- الملفات: `src/gateway/tls.ts`، `src/gateway/server.ts`، `src/config/env.ts`، `.env.example`، `test/nativeTls.test.ts` + `test/helpers/setTlsTestEnv.ts`.
- الأدلة: 7 اختبارات جديدة 7/7 (عميل TLS يثبّت الشهادة، 200 + HSTS، المصادقة ما زالت تُفرض 401/200، HTTP صريح إلى منفذ TLS بلا رد، عميل لا يثق بالشهادة يُرفض)؛ **فحص تحوير**: تعطيل مسار TLS يُفشل 4 اختبارات؛ الحزمة الكاملة **761/761** (754 الأساس + 7)، `tsc --noEmit` نظيف، `npm run build` ✓، وتشغيل عملية `dist/` حقيقية: HTTPS مع تثبيت الشهادة 200 وHTTP العادي بلا رد وضبط أحادي الجانب يُجهض.
- لم تُكتب الاختبارات قبل الشيفرة (ليست دورة Red→Green موثّقة)؛ بدلًا منها فحص التحوير أعلاه.

## 2) جدول جاهزية الإنترنت (صريح)
| البند | الحالة |
|---|---|
| TLS داخلي | VERIFIED (محليًا، شهادة موقّعة ذاتيًا؛ شهادة CA عامة وتجديد تلقائي: UNVERIFIED) |
| مفتاح بوابة مشترك (≥16 حرفًا، يرفض الإقلاع بدونه خارج loopback) | موجود وVERIFIED سابقًا (`deploymentGuard`)؛ **مفتاح واحد مشترك = كل من يعرفه يستهلك رصيدك** |
| محدّد معدّل الفشل لكل IP + CORS بقائمة بيضاء + HSTS + ترويسات أمان | موجود وVERIFIED سابقًا |
| سقف إنفاق يومي `NEXUS_DAILY_BUDGET_USD` | الكود موجود؛ **لم أعد اختباره مع مزود حقيقي** (UNVERIFIED هنا) |
| مصادقة لكل مستخدم / عزل مستأجرين | غير موجود |
| حماية DoS/WAF على الحافة، مراقبة، نسخ احتياطي، إدارة أسرار، اختبار اختراق | غير موجود / غير مُنفَّذ |
| وسيط MQTT (`NEXUS_MQTT_PORT`) وتنفيذ الشيفرة (sandbox) | معطّلان افتراضيًا — **أبقِهما معطّلين** عند التعرّض للإنترنت |

## 3) ما أحتاجه منك (لا أستطيع إنشاؤه نيابةً عنك)
1. **استضافة:** خادم VPS صغير + اسم نطاق يشير إليه. أعطني وصولًا (مثلًا مفتاح SSH/رمز API للمزوّد في env على جهازك) أو نفّذ أنت الأوامر التي أجهّزها.
2. **شهادة:** Let's Encrypt (certbot/Caddy) للنطاق ⇒ ملفا `fullchain.pem` و`privkey.pem`.
3. **مفتاح البوابة:** `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"` — يوضع في env فقط، لا في ملف ملتزَم به.
4. **مفاتيح المزودين:** أنشئها من لوحات المزودين (Anthropic/OpenAI/…)، **وفعّل حدّ إنفاق شهريًا داخل لوحة المزود نفسه** (حماية مستقلة عنا)، ثم `NEXUS_*_API_KEY` في env مع `NEXUS_DAILY_BUDGET_USD=<سقف>`.
5. التشغيل: `NEXUS_HOST=0.0.0.0 NEXUS_TLS_CERT_FILE=… NEXUS_TLS_KEY_FILE=… NEXUS_GATEWAY_KEYS=… NEXUS_CORS_ORIGINS=https://<نطاقك> npm start` ثم `node e2e/real-provider-validation.mjs` من جهاز يملك المفاتيح.
**قبل فتح الخدمة للعامة:** شريحة تقوية معتمدة (مصادقة لكل مستخدم، حدود معدّل على الحافة، مراقبة) — لا أبدؤها دون موافقتك لأنها تغيّر نموذج الأمان.
