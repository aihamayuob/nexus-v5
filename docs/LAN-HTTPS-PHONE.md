# NEXUS — تشغيل الصفحة من الجوال على نفس الشبكة (HTTPS محلي) — 2026-11-21

**الحالة:** السكربت `scripts/nexus-lan-https.mjs` **VERIFIED ضمن حدود مذكورة في §5** (35/35 في `e2e/lan-https-phone-flow.mjs`، نماذج محاكاة). **جهاز حقيقي ثانٍ على شبكة Wi-Fi حقيقية: UNVERIFIED** (لم يُجرَّب هنا).
للاستخدام المحلي/شبكة موثوقة فقط. ليس نشرًا على الإنترنت.

## 1) لماذا
المتصفح يعطّل WebCrypto وService Worker خارج «السياق الآمن». فتح `http://192.168.x.x` من الجوال لا يُقلع (`docs/DEPLOYMENT-LAN.md` §4). هذا السكربت يضع أصل **HTTPS واحدًا** على عنوان الجهاز الخاص يقدّم الصفحة ويمرّر `/api /v2 /mcp /health` إلى الخلفية التي تبقى على `127.0.0.1`. هو المكافئ داخل المستودع لـ `docs/DEPLOYMENT-TLS.md` (nginx) بلا اعتماديات.

## 2) الخطوات (على الحاسوب، مرة واحدة ثم عند كل تشغيل)
```bash
npm --prefix src-baseline/nexus-backend ci && npm --prefix src-baseline/nexus-backend run build   # مرة واحدة
node scripts/nexus-lan-https.mjs                    # يختار عنوان IPv4 الخاص تلقائيًا
# أو: node scripts/nexus-lan-https.mjs --host 192.168.1.20 --port 8443
# اختياري للصفحة ذات الملف الواحد: node scripts/build-single-file.mjs
```
يطبع: رابط الصفحة، **عنوان API (نفس الأصل)**، **مفتاح البوابة**، وبصمة SHA-256 للشهادة.

## 3) على الجوال (نفس شبكة Wi-Fi)
1. افتح الرابط المطبوع `https://<عنوان-الحاسوب>:8443/NEXUS-Standalone.html`.
2. سيحذّر المتصفح من الشهادة (موقّعة ذاتيًا): قارن البصمة إن أمكن ثم تابع.
3. تبويب «الاتصال»: **عنوان API = نفس الأصل** (`https://<عنوان-الحاسوب>:8443`) + مفتاح البوابة المطبوع. المفتاح يبقى في ذاكرة الصفحة فقط.
- للشهادة الموثوقة بلا تحذير: استعمل `mkcert` وثبّت جذره على الجوال ثم `--cert` و`--key` (**UNVERIFIED** هنا).
- إن لم يظهر شيء: شبكة ضيوف/عزل العملاء (AP isolation) تحجب الجوال عن الحاسوب؛ وجدار حماية النظام قد يطلب السماح لـ Node على الشبكات الخاصة.
- السكربت يحتاج `openssl` لتوليد الشهادة (على ويندوز: Git for Windows يتضمنه) أو تمرير `--cert/--key`.

## 4) ما يُفرض في الشيفرة (مُختبَر)
| الضمان | الدليل |
|---|---|
| يرفض `--host` غير الخاص (0.0.0.0، اسم مضيف، عنوان عام، CGNAT، نطاقات التوثيق) | E2E: 4 رفض + منطق `isPrivateIPv4` |
| يدمّر أي اتصال TCP من عنوان غير خاص قبل TLS (منع port-forward من الإنترنت) | منطق `isAllowedPeer` مُختبَر؛ **اتصال عام حقيقي لم يُجرَّب** |
| الخلفية لا تُعرَّض: على العنوان غير loopback الموجود في البيئة منفذا الخلفية والواجهة يرفضان الاتصال | E2E bind check |
| مسارات محدودة: الصفحتان + `/api /v2 /mcp /health` فقط؛ غيرها 404، POST للصفحة 405، ملف المفتاح غير قابل للوصول | E2E |
| `X-Forwarded-For/Forwarded/X-Real-IP` الواردة تُسقَط، و`XFF`=عنوان النظير الحقيقي؛ الخلفية تثق بـ127.0.0.1 فقط | E2E: 14 طلبًا بمفاتيح خاطئة مع XFF منتحل ⇒ 401 ثم 429 |
| CORS = أصل الصفحة HTTPS فقط، لا `*` | E2E |
| شهادة EC P-256، SAN للعنوان+localhost، serverAuth، ليست CA، 30 يومًا، المفتاح بصلاحية 600 داخل `.nexus-lan-tls/` المُتجاهَل في git | E2E |
| صفحة HTTPS = سياق آمن: `isSecureContext` و`crypto.subtle` ✓، اتصال حي، مهمة تكتمل عبر الوكيل، لا مفتاح في التخزين/الكونسول، لا انتهاكات CSP، لا تجاوز أفقي على 390px، أهداف اللمس ≥24px (الخانات تُقاس كـ label) | E2E (Chromium) |

## 5) حدود غير مُثبتة (UNVERIFIED / غير مُوفَّر)
- جهاز حقيقي ثانٍ، Safari/iOS، Chrome Android، Firefox؛ سلوك الاستمرار بعد تجاوز تحذير الشهادة على كل متصفح.
- اتصال خارجي حقيقي من عنوان عام (فلتر النظير مُختبَر منطقيًا فقط).
- شهادة CA موثوقة (mkcert/Let's Encrypt).
- لا حماية DoS/معدّل على مستوى الوكيل (الخلفية تطبّق محدّد معدّلها)، ولا دعم ترقية WebSocket عبر الوكيل (مرفوضة عمدًا).
- الأصل الوحيد المُختبَر في البيئة كان loopback (لا واجهة LAN خاصة في الـsandbox)؛ لذلك المسار `--host <LAN-IP>` يعتمد على نفس الشيفرة لكنه لم يُشغَّل على عنوان خاص حقيقي.
- WCAG 2.2 AA: غير مُقيَّم.
